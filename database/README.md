# قاعدة بيانات بلوت 450

هذا المجلد يحتوي مخطط MySQL للبنية متعددة اللاعبين.

## المتطلبات
- MySQL 8.0+ أو MariaDB بإصدار يدعم InnoDB وقيود CHECK.
- PHP 8.1+ مع PDO MySQL.
- قاعدة بيانات منفصلة للمشروع ومستخدم محدود الصلاحيات.

## إعداد PHP
عرّف المتغيرات في بيئة PHP/FPM أو ملف إعدادات خارج `public_html`:

- `BALOUT_DB_DSN=mysql:host=127.0.0.1;dbname=baloot450;charset=utf8mb4`
- `BALOUT_DB_USER=...`
- `BALOUT_DB_PASSWORD=...`

لا تضع كلمة المرور في المستودع أو داخل مجلد الويب. لا تستخدم مستخدم MySQL بصلاحيات عامة.

## التهيئة
راجع `schema.mysql.sql` وخذ نسخة احتياطية قبل تطبيقه يدوياً على قاعدة بيانات فارغة مخصصة للمشروع. لا يوجد تشغيل تلقائي للمخطط من PHP.

## تصميم التزامن
- `baloot_rooms`: صف واحد لكل غرفة، و`version` يتزايد مع كل تعديل.
- `baloot_room_players`: مقعد واحد لكل لاعب في الغرفة، مع منع تكرار المقعد ومعرف اللاعب.
- `baloot_room_actions`: سجل مفتاح idempotency لكل عملية لمنع تنفيذ الحركة مرتين عند إعادة إرسال الطلب.
- تتم التعديلات داخل معاملات InnoDB مع `SELECT ... FOR UPDATE` على صف الغرفة.

## تنبيه
طبقة التخزين لا تعني أن واجهات اللعب أو دورة البلوت اكتملت. لا تنشرها منفردة ولا توصلها بالواجهة قبل اكتمال API والتحقق من صلاحيات كل حركة واختبارات التزامن.

## PHP API والمهل التلقائية
- واجهة الغرف: `/api/room.php`، وتستخدم cookie ضيف آمنة من نوع HttpOnly وSameSite=Lax.
- اضبط `APP_ORIGIN` على أصل الموقع الكامل، مثل `https://example.com`.
- شغّل `/api/cron.php` من CWP Cron كل دقيقة باستخدام PHP CLI؛ المهمة تستعيد المهل المنتهية، وتكمل مقاعد البوت، وتنهي مهلة القيد، وتبدأ التوزيعة التالية بعد مهلة النتيجة.
- لا تفتح ملف cron عبر الويب دون `BALOUT_CRON_SECRET` قوي؛ عند التشغيل من CLI المحلي لا يحتاج إلى HTTP token.
- مثال cron بعد استبدال المسار بمسار حساب الاستضافة:
  `* * * * * /usr/local/bin/php /home/ACCOUNT/public_html/api/cron.php >/dev/null 2>&1`

لم يتم تهيئة متغيرات البيئة أو تشغيل المهمة على السيرفر. لا تنشر قبل مراجعة إعدادات CWP ونسخة احتياطية واختبار اتصال MySQL.
